# Validation record, 2026-09-02, A100-SXM4-80GB, CUDA 12.4 nvcc, torch 2.10.0+cu128, triton 3.6.0

This was the model validation record the project pointed every worker at (environment, what ran, what passed, what was skipped and why, what is still unverified).

Executed §4-§6 top to bottom. §7 skipped (`evaluation/data/arxiv-papers/` not on the box). §8 ncu blocked by `ERR_NVGPUCTRPERM`; per-kernel times from `torch.profiler`.

- build: ok, 52 s cold, cache no-op warm. SASS: `IDP.4A.S8.S8` present, no `LDSM`, no `BAR.SYNC` in the scorer.
- parity: 47/47 bit-exact. Only full-suite failures were two Triton compile tests: `common.<jit helper>` attribute references do not survive inductor's kernel re-serialization; fixed by importing `bloom_subset_pass` / `clause_pass` by name.
- As shipped the CUDA path was slower than Triton at every B=16 large-P regime (scorer 188 µs vs 85 µs unfiltered): one 128 B row per warp in flight. Fixes (commit `0f7792c`), keeping API, config fields and bit-exactness:
  1. scorer lane layout `SEG = D/16`, one `int4` per lane (a warp keeps `SPW·UNROLL` rows outstanding), ids pipelined one iteration ahead, `__ldcs` row loads;
  2. clause mask thread-per-slot with a `(C, A_max)` template fast path loading the attribute row into registers (101 -> 56 µs);
  3. `DEFAULT_CONFIG = (block_p=128, num_warps=8, unroll=1)` (was 256/4/1).

Gates: (1) correctness pass; (2) bloom >= 1.0x everywhere, 1.3x at large P (kernel-only 2.1x; the shared topk epilogue is ~60 % of wall time at these shapes); (3) no filter within +-10 %, pass (-3 % worst); (3b) exact within +-10 %, pass (-3 % worst); (4) e2e not run.

Finding for the paper: the 2-4x kernel-level bloom win holds only after fix 1. The transposed-index traffic saving was real from the start (~40x fewer filter bytes) but hidden behind the scorer's missing memory-level parallelism. The remaining exact gap is the standalone clause kernel paying the random attribute gather serially before the scorer; fusing the predicate into the scorer (Triton's structure) would be next.

Outcome: deleted at roadmap B4 (2026-09-06) once Meta's official ops passed the B2 parity gate; tag `cuda-cute-backends-final`. The transposed-index idea returns to Triton as plan O §8 TF-1 (`build_transposed_sigs` / `words_per_cluster` kept in `indexing/bloom_hash.py`).
