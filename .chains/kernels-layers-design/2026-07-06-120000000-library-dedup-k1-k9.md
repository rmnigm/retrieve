# `retrieve` kernels + layers design improvements (K1-K9)

Source: `docs/plans/kernels-layers-design.md`. Implemented 2026-07-06 on `refactor/kernels-eval` (line refs against `2b1ff80`); library test gates passed on the A100 2026-09-02 (refactor-validation-handoff chain). Structure-preserving: dedup and re-homing, no observable output or launch-shape change.

## 1. Intent
The debt was duplication at three levels plus one broken tool: host wrappers repeated prep + launch args + epilogue in `_impl` and one or two `@triton_op`s (validation only in `_impl`, so production ops were the unvalidated path); the exact-clause predicate written three times, the bloom subset test three times in two algebraic forms, the compaction epilogue twice; `SimHashKNN` a ~95 % copy of `OneBitKNN`; the masked top-K epilogue six times; two near-identical bloom builders consumed by SilverTorch through private imports; `tune.py` six copies of one skeleton with a broken `codesigned-probe-score` subcommand.

## 2. Invariants (every phase) - still in force
1. Bit-exactness: the parity suite passes unmodified; OPORP / SimHash strict equality.
2. `wrap_triton` stays textually inline in every `@triton_op` body (torch.export walks the decorated function's source).
3. `retrieve::*` op schemas frozen.
4. Buffer names and registration order frozen: `item_embs`, `item_embs_t`, `item_codes_t`, `item_bits`, `oporp_signs`, `oporp_perm`, `simhash_R`, `centroids`, `item_codes`, `global_scale`, `padded_cluster_items`, `cluster_sizes`, `bloom_sigs`, `hash_seeds`, `item_clause_attrs`, `clause_is_reverse`.
5. GPU suite green at every phase boundary. 6. K2 / K3 perf within +-5 % on `tune-kernels`.

## 3. Phases
- K1: `tune-kernels codesigned-probe-score` called the public op with kwargs Stage 2b had removed (TypeError on the first point); call `_impl`; CUDA-gated `test_tune_smoke.py`.
- K2: per kernel file `_<name>_prep` (validation, contiguity, buffers, launch kwargs in a frozen `_<Name>Launch`) and `_<name>_finish`; every entry point prep -> one launch line -> finish (~348 -> ~210 lines on `codesigned_probe_score.py`). `fused_masked_knn_topk`'s intentional public-vs-`_impl` difference made explicit as `bucket=` / `pad_to_k=`. Tracing caveat (dataclass + kwargs splat under `make_fx`) with a plain-tuple fallback.
- K3: `common.py` `@triton.jit` helpers (`or_combine`, `popcount_int64`, `bloom_subset_pass`, `clause_pass`, `compact_store`); bloom kernels standardize on `qb & ~sig` OR-reduce. Non-goal: merging the two probe scorers into one kernel with a constexpr matrix (two clean schemas beat dummy params and coupled register pressure).
- K4.1: `masked_topk` / `counts_to_valid` replace six epilogues; per-call-site table pinned behaviour (`OneBitKNN` candidates path and `SilverTorch._forward_candidates` keep `pad_to_k=False`).
- K4.2: `_PackedBitsKNN` base (subclasses own `_quantize_index`, `_project_query`); `_oporp_project` shared.
- K4.3: SilverTorch `register_index` split (validate / IVF / quantize / filter buffers, order frozen); `forward(query_clause_attrs=..., candidate_ids=...)` raises instead of silently dropping the predicate; `clause_subset_match` / `bloom_subset_match` shared with the filters (SilverTorch shares the predicate math, never holds `FilterModule` instances: the in-model fused filter is the paper's point); `filter=` -> `filter_mode=`.
- K4.4: `FullScanKNN` post-filter semantics documented (LiNR baseline: winners tombstoned to `-1`, not backfilled).
- K5: `bloom_hash.py` with `_signature_batch` core shared by chunked `build_signatures` and loop-free `build_query_signatures` (a Python `range()` makes dynamo specialize on trip count); hash math untouched; new equivalence test.
- K6: `FilterModule.register_index(item_clause_attrs, *, clause_is_reverse=None)` (a positional `clause_is_reverse` to `BloomFilter` used to land in the speculative `item_embs` and be ignored); minimal `RetrievalModule` ABC constraining only the lifecycle; docstring fixes (`PostfilterKNNInt8` tie-introducing range shift; full-width compact contract).
- K7: `KernelTuneSpec` registry, seven generated subcommands incl. new `codesigned-probe-score-exact`.
- K8: tests (`test_topk_util.py`, tune smoke, `evaluate_subset` equivalence, kw-only lock, builder equivalence, candidates+qa raise, short-row `_forward_candidates`).
- K9: system-doc sweep.

## 4. Catalogued design gaps and their later fate
1. State-dict round trip on fresh modules and stale `_global_scale_f`: delivered as a load post-hook (review #4) and the builders' `load_prebuilt` (L2).
2. `KMeansTorch` not k-means++ (paper §3 cites Arthur & Vassilvitskii): delivered opt-in at L2 (`kmeans_init="kmeans++"`).
3. `OneBitKNN.k_bits` sentinel mutation on re-register: fixed in K4.2 (pristine constructor arg).
4. Re-registration: documented "register once" in the ABC.
5. `_int_mm` M >= 17 padding constant: comment.
6. `combine_indices` host sync per stage: documented, not for captured paths.
