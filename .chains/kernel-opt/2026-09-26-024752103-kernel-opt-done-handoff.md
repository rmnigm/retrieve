## Findings for the orchestrator
1. **Committed D1 records exist** (`evaluation/results/filter/goodreads-d128.jsonl`, 126 cells) — the brief assumed none. `code_version` changed, so `bench campaign --resume` will re-run that leg (~19 GPU h). Quality on the new code is identical to those records on every comparable cell; SilverTorch perf numbers will differ (faster).
2. **Stale inductor cache**: the FX-graph / AOT-autograd caches replay an *old* `triton_op` body after it is edited (4 compile gates failed with the pre-change width on the warm `/tmp/torchinductor_root`, passed cold). Any graph-mode harness run on this box after a library change can silently run stale code. Harness-side fix suggested (cache dir keyed by code_version). Documented in testing.md § Running and validation.md "Still unverified".
3. Inductor passes `global_scale` into a Triton kernel as a Python float; `.to()` on it broke TTIR analysis and the compiled forward returned **NaN silently** (warning only). Fixed with `tl.cast`.
4. Golden gate row was stale: linr_v2 4.5e-4 / linr_v3 1.7e-5 differ from the golden JSONs on the pre-change code too (cause unidentified, predates this branch). validation.md corrected.
5. `docs/decisions.md`'s "~40 GB at 10M" pubmed estimate counts steady state only, not the build transient (sibling E2 finding) — not edited here (decisions are the user's); worth correcting.
6. `c4_gate.py` can no longer match today's records (expects status ok at algo defaults; SilverTorch cells carry n_probe params) — replaced here by `docs/artifacts/kernel-opt/golden_compare.py`.
