# Q3: harden the library's correctness gates (GPU)

## 1. Request
Roadmap Q3. Several library gates are weaker than they claim. Strengthen them inside the existing test files (no new suites, no scaffolding), then report every test that turns red as a finding. Rule 3: never loosen a tolerance; a red gate is reported, not relaxed. Ideas only; cite only this repository.

## 2. Known defects in the gates (verified by reading; not run)
1. **Non-finite values are masked.** `retrieve/tests/parity/conftest.py:116-118` replaces every non-finite score with 0 before `allclose`, so −inf vs 0, NaN vs −inf and +inf vs −inf pass. In the 1-bit path (`test_oporp_1bit_match_topk.py`) scores are integers D−2·hamming and 0 is common. Fix: assert `torch.equal(isfinite(a), isfinite(b))` (and equal signs of the infinities), compare finite values only; on failure print the count, first indices and both values. Integer-valued paths (oporp/simhash) compare with `torch.equal`.
2. **Default tolerances leak.** `assert_topk_matches` and `assert_topk_id_sets_match` default `atol=rtol=1e-3`. Make them keyword-only with no default; each call site states its tolerance and a one-line reason.
3. **Compile test never replays.** `retrieve/tests/compile/test_silvertorch_compile.py:59-66` calls the `reduce-overhead` module once (warm-up under cudagraph trees) and uses `assert_close` while its comment says bit-identical. LiNR graph tests (`tests/compile/test_linr_compile.py` ~139, `tests/correctness/test_linr.py` ~619) replay with the query they warmed on. Fix: warm up, then run ≥2 *different* inputs and compare each against eager on the same backend with `torch.equal` on scores and ids-up-to-ties.
4. **Poisoned-output coverage.** Only `fused_masked_knn_topk` has a test that fills `torch.empty` with poison to prove the kernel writes every slot. Add it for `codesigned_probe_score`, `codesigned_probe_score_exact`, `oporp_1bit_match_topk`; count calls to the patched allocator so the test fails if the allocation moved and the poison was never used.

## 3. New gates (each a few lines in an existing file, bit-exact)
- **Inputs unchanged**: every public op declares `mutates_args=()`; clone inputs, call, `torch.equal` each input afterwards.
- **Cutoffs from the code's own constants**: import the bucket ladders (`_P_BUCKETS`) and `DEFAULT_CONFIG.block_n`; run kernels at bucket−1/bucket/bucket+1 and at `p % block_n ∈ {0,1}`; assert inside the test that the input really lands in the intended regime.
- **Degenerate rows**: count=0 and count=1 rows return exact `(-1, -inf)` sentinels in the unused slots (the pattern already exists in `test_fused_masked_knn_topk.py`; apply to the other top-k kernels).
- **Identities between variants**: indirect oporp with ids=`arange(N)` `torch.equal` the direct path; `codesigned_probe_score` with an all-pass query bloom equals the no-bloom op; `clause_compact` equals compacting `clause_mask`'s output. Catches a constexpr keyed to the wrong variant or a reused compilation.
- **Oracle-free identities** where the reduction is row-local: row b run alone equals row b in the batch; permuting the item table permutes ids and leaves scores equal (exact paths only).
- **Reference twin coverage**: every op in `torch.ops.retrieve` has a same-named, same-signature callable in `retrieve.ops.reference` (docs/system/kernels.md claims it; nothing checks it). Anti-vacuity: assert the op list is non-trivial.
- **Official op schemas pinned**: compare `str(torch.ops.st.<op>.default._schema)` against the strings for the pinned commit; skip-vs-fail through the existing `require_official`.
- **`torch.library.opcheck`** on the two ops with `register_fake` (`clause_compact`, `bloom_compact`).
- **Structural footprint (feasibility first)**: record the aten ops/allocation shapes a module forward issues (TorchDispatchMode) and assert no `[B,N,C,A_max]`- or `[B,P,D]`-sized intermediate. Custom ops may be opaque to the recorder — check on the box; if it only sees module level, gate SilverTorch and LiNR V1-V4 forwards; if useless, record why and drop.
