## Plan amendments I made, and why

1. **gBCE samples negatives per position; only `sampled_softmax` uses one shared vector.**
   With one shared `[256]` vector per step (plan §3), gBCE collapsed: test 0.0160 / 0.0377,
   coverage@10 1.6e-5, early stop at epoch 47.
   - What happens (`diag_collapse.py`, `shared-k256-collapse.json`):
     - The whole run draws only ~2 negatives per item (47 × 358 × 256 = 4.3 M over 1.87 M
       items). Per-position sampling draws 12 M per step.
     - So almost no item's output row ever gets pushed away. Rare items stay at their initial
       norm: 0.186 vs 1.05 published.
     - The positive pull grows the popular items' rows.
     - Every query in a batch is pushed away from the same 256 rows, so nothing separates users.
     - User queries end up nearly identical (mean pairwise cosine 0.9988 vs 0.37 published).
       Across 2048 users' top-10s there are 21 distinct items, all among the 0.1% most frequent.
   - Ruled out:
     - Dataset, mask and eval path: a 2-epoch control through the same code with only the
       sampling switched to per-position reproduced the published curve (epoch-0 loss 0.0678 vs
       0.0688; epoch-1 val ndcg@10 0.0199 vs 0.0200).
     - Frozen negatives: they are redrawn every step.
     - gBCE alpha: identical per row in both schemes.
     - Positive/negative collisions: rate ~1.4e-4 in both schemes.
     - Larger shared K: it made things worse (epoch-1 val 0.0118 at K=4096, 0.0003 at
       K=32768).
   - Consequence: the plan's KuaiRand memory argument for shared negatives does not hold for
     gBCE. The per-position gather costs about 6 GB more at this shape (11.2 vs ~4.5 GB peak).
2. **No `loss_chunk`.** Autograd keeps every chunk's logits for the backward pass, so chunking
   without recomputation saves no memory. Sampled-softmax logits are computed in fp32 outside
   autocast.
3. **One fused AdamW; gradient clipping over all parameters, as published.** The two-optimizer,
   body-only clipping design existed for row-wise Adagrad, which amendment 1 dropped.
4. **The train split lives on the GPU.** Batches are `randperm` slices of device-resident
   tensors, instead of the plan's pinned host tensors with `non_blocking` copies.
5. **`normalize` lives on the model.** `Encoder.scoring_table()` and `predict_last` return
   unit vectors when `normalize` is on, so evaluate, encode and `item_embs.pt` all score cosine
   from one place (A1).
6. **`train run` takes `TrainConfig` `FIELD=VALUE` pairs** (plus `--config` and `--resume`)
   instead of one click flag per field.
7. **HSTU uses softmax SDPA with the bias as an additive float mask**, as amendment 1 says.
   Each HSTU block has its own `RelativeBias` (position buckets, plus log-1.5 time-delta buckets
   under `use_time`). LlamaBlock, `attn_bias`, logQ, row-wise Adagrad and the bf16 table are not
   implemented (amendment 1).
