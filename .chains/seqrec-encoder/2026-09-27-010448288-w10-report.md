# W10 report: `train_on_val` (final fit on train + val)

Commit `91e3763` on `dev/hstu-trainval`, not pushed and not merged. CPU only; no GPU was used.

## What changed
- `TrainConfig.train_on_val: bool = False`.
- `dataset.load_val_transitions` turns each `val.parquet` row into a train-shaped row: the last `L+1` tokens of
  `item_ids ++ targets`, left-padded. In all three ETLs `targets` is the val-day clicks in time order, and the
  KuaiRand clicks are sorted by `time_ms`. It also returns `first = max(L − n_targets, 0)` per row.
- `dataset.target_mask(items, first)` is `(items[:, 1:] != 0) & (j >= first)`. It is the one definition of a
  trained target position, and both `step_loss` and `target_frequencies` (logQ) use it. Train rows have
  `first = 0`, so the mask equals the old `targets != 0`. The logQ counts are identical to before, and no RNG
  draws were added: a run with `train_on_val=false` computes the same thing as before. `target_frequencies` now
  does a masked select instead of the flat whole-tensor bincount. That costs a transient copy of the trained
  positions (~0.9 GB at KuaiRand) once at startup.
- With `train_on_val=true`, `train()` concatenates the val rows onto the train rows. `do_eval` is always false,
  so there is no val eval, no snapshot and no early stop. It runs exactly `num_epochs`, and the last epoch is
  saved as `best_model.pt` and scored on test into `eval_quality.json`. `best_val_metric` is `{}` rather than
  `-Infinity` (invalid JSON).
- **Rejection: none added.** With `train_on_val` the val path is off completely: `stopping` needs val metrics,
  which never exist. So no val-based early-stop requirement can apply silently. `patience`, `eval_every` and
  `early_stop_metric` simply have nothing to act on, as `datasets.md` now says.

## Design choice: mask to the target positions (no double training)
Masking was cheap: one int64 per row (`first`) plus one comparison inside the existing mask. It avoids the
duplicates entirely, because a val row's history transitions are already train rows. The arithmetic on
`/data/kuairand/val.parquet` (L=200, 24,503 rows): an unmasked val row would carry 4,892,608 transitions, of
which **2,000,675 (41 %) duplicate train transitions**. Masked, 2,891,933 val-day transitions are trained.

**Caveat, following the brief's "tail like a train row":** 6,875 val users have more than 200 val-day clicks.
The tail keeps only the last 200 of those clicks, so **979,261 of the 3,871,194 val-day transitions (25 %) are
not trained.** Windowing val rows the way `train_windows` does for train would cover all of them. That is a
follow-up for the orchestrator to decide, not part of this change.

The refit adds 24,503 rows to 561,486, so an epoch is 2,288 batches instead of 2,193 (+4.4 %) at batch 256.

## Tests (`tests/training/test_encoder.py`)
- `test_train_on_val_rows_are_the_tail_of_history_then_targets`: a hand-built 4-row parquet at L=4. It pins
  the rows (appending order, the tail, left padding, more targets than L), `first`, the trained targets under
  `target_mask`, and the `target_frequencies` counts.
- `test_train_on_val_runs_no_val_eval`: a tiny CPU `train()` with `evaluate` monkeypatched. It asserts that
  evaluate is never called and that `best_model.pt` is written.
- Mutations run by hand, each one failing a test: dropping `not config.train_on_val` from `do_eval`; dropping
  the `first` term from the mask; swapping the concat order; an off-by-one in `first`.

```bash
uv run --directory evaluation train run data_dir=/data/kuairand \
    checkpoint_dir=/scratch/ckpt/k64tv-sasrec-ssm-logq wandb_run_name=k64tv-sasrec-ssm-logq \
    num_epochs=4 train_on_val=true
uv run --directory evaluation train run data_dir=/data/kuairand \
    checkpoint_dir=/scratch/ckpt/k128tv-sasrec-ssm-logq wandb_run_name=k128tv-sasrec-ssm-logq \
    embedding_dim=128 ffn_hidden_dim=512 reuse_item_embeddings=true \
    num_epochs=4 train_on_val=true
```
- **k128:** `reuse_item_embeddings=true` follows the "one table" k128 probe plan. Confirm it against that
  probe.
- **`resume_every`:** at 4 epochs, `resume_every=5` writes `_resume.pt` only on the last epoch. Keep the
  default of 1 if crash-safety per epoch is wanted.
- **Unverified:** nothing ran on the GPU. The GPU memory of the extra rows is tiny (24.5k × 201 int64), but it
  was not measured.
