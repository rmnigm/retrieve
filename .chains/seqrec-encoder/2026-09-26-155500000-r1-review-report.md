# R1 review report: dev/hstu-encoder

**Verdict: CLEAN-AFTER-FIXES.** One commit on `dev/hstu-encoder`: `3e8102b` (not pushed, not merged).
I reviewed the diff `git diff dev/hstu...dev/hstu-encoder` with deslop and python-review. No GPU was used.

## Fixes applied

- **`--resume` crashed on the GPU** (`evaluation/training/train.py:150`). `torch.load(..., map_location=device)`
  moved the saved RNG states onto CUDA. `torch.set_rng_state` and the CUDA generator's `set_state`
  accept CPU ByteTensors only, so they raise `TypeError: RNG state must be a torch.ByteTensor`. I
  reproduced that error on CPU with a `meta` tensor. The fix loads with `map_location="cpu"`, and
  `load_state_dict` moves the model and optimizer state to the device. The bug predates this diff.
  No CPU test can pin it, and it has still never run on the GPU.
- **`TrainConfig` accepted an unknown `loss`** (`config.py:__post_init__`). `step_loss` only checks
  `loss == "gbce"` and sends any other value to `sampled_softmax`. So a typo like `loss=gbc` trained
  sampled softmax without normalization and recorded `gbc` in `config.json`. It now raises a
  `ValueError`.
- **`normalize=True` with `gbce` was ignored in the loss but used everywhere else.** `gbce_loss` scores
  raw dot products, while `scoring_table`, `predict_last`, evaluate, encode and `item_embs.pt` score
  cosine. So the run trained one metric and was measured on another. `TrainConfig` now rejects the
  combination.
- The two config fixes are pinned by `test_train_config_rejects_what_the_loss_would_silently_ignore`
  in `tests/training/test_encoder.py`, which has two cases. Both cases fail without the fix.
- **Dead attributes:** `Encoder.num_items` and `Encoder.max_seq_length` were never read, so I deleted
  them.
- **Docs:**
  - `docs/system/datasets.md` § The losses said shared-negative gBCE "stalls at loss ≈ ln 2". No
    artifact supports that. It now says what was recorded: the user queries collapse onto a few
    popular items. It also documents the new config rejection.
  - `docs/validation.md`: the unit-gate row now lists the config check, and the unverified list
    notes that `--resume` has never run on the GPU.

## Checked and found correct

- **Attention mask:** `causal & (key_valid | eye)`. Real rows see exactly their real causal prefix,
  and padding rows see only themselves, so no row produces NaN. SASRec inverts the mask to the
  `src_mask` convention (`True` = blocked) and repeats it per head. HSTU applies `-inf` via
  `masked_fill` before the float bias.
- **Time gap:** `F.pad(key_valid, (1, -1))` zeroes the gap at the first real item.
- **Sampled softmax:**
  - The positive column comes first and uses the same normalization and temperature as the
    candidates.
  - A candidate equal to the row's own positive is masked to `-inf`. This covers the in-batch copy
    of the row's own positive and other rows sharing that item.
  - The logits are fp32 outside autocast.
- **gBCE:** the float64 calibration matches the old code. `alpha = K/(N-1)`, and the negatives are
  drawn per position.
- **`load_model_for_eval`:**
  - The `encoder.layers.N.` → `blocks.N.` rename covers every GSASRec key. `SASRecBlock` subclasses
    `TransformerEncoderLayer`, and the old encoder had no `norm`.
  - `TrainConfig.load` drops `negs_per_pos` from old `config.json` files, and a missing
    `loss`/`normalize` resolves to gbce / False.
  - `D128_DROP05_DEFAULTS` builds with `encoder="sasrec"`.
- **Resume state:** the resume file saves and restores every RNG (Python, numpy, torch, CUDA).
- **Leftovers:** no GSASRec code or old `train sasrec` / `GSASRecConfig` wording remains in the
  code, `docs/system`, README or AGENTS.
- **Citability:** `docs/validation.md` § Seqrec encoder rewrite says "not yet validated, not
  citable", and no number elsewhere in the diff is presented as citable.

## Open findings (behaviour changes, not fixed)

1. **`train.py:147`: `--resume` without `_resume.pt` silently starts a fresh run.** This is the
   `resume and resume_path.exists()` fallback, and it predates this diff. It should probably raise.
2. **`train.py:137-170`: a resumed run's `train_metrics.json` covers only the resumed epochs.**
   `epoch_losses`, `epoch_times`, `val_metrics_per_epoch` and `sm_mhz` are not saved in
   `_resume.pt`, and `t0` restarts. So `samples_per_sec` and `total_time_sec` describe only part of
   the run.
3. **`docs/system/checkpoints.md:51` still lists `negs_per_pos=256`.** That is correct as the
   published runs' config key, but the current field is `num_negatives`. A one-word note would help
   anyone copying it into `train run`.
4. **`evaluation/eval_datasets/hub.py` is not ruff-formatted** (aligned dict literals). This
   predates the diff, and the brief accepts it. I left it untouched.
