# R11 review: dev/hstu...dev/hstu-trainval

**Verdict: CLEAN-AFTER-FIXES.** Fix commit `40383ef` on `dev/hstu-trainval`, on top of W10's `91e3763`. It is not
pushed or merged. CPU only; the GPU was not used.

## What I checked (all hold)
- **`train_on_val=false` changes nothing.** I compared the old flat-bincount `target_frequencies` and the old
  `targets != 0` mask with the new `target_mask` path over 50 random left-padded `[37, 10]` tensors (including
  all-padding rows): `torch.equal` on both. No RNG draws were added: `train_batches` still does one `randperm`,
  and indexing `first[idx]` draws nothing.
- **Off-by-ones.** Target position `j` is `items[:, j+1]`. The last `n` columns `L+1-n..L` are the val targets,
  so they are target positions `L-n..L-1`, and `first = L-n` is correct. When `n > L`, the clamp to 0 trains all
  `L` positions, and the row's column 0 (itself a val click) is input only. That matches the docs' "keeps only
  its last `max_seq_length`".
- **Last epoch saved and test-scored.** `best_path` stays `None` because there are no val metrics. `best_model.pt`
  is therefore the model after the last epoch, and test is scored on it. On resume, `_resume.pt` restores the
  model, the loop finishes the remaining epochs, and the snapshot prune finds nothing. `resume_due` still writes
  the last epoch (`stopping` is always false).
- **Docs and citability.** `datasets.md` matches the code. `validation.md` is untouched, and no number is
  presented as citable.
- **Deslop.** No Tier A/B/C items in the diff. `# fmt: skip` in the tests follows the house style (see `tests/bench`).

## Fixes applied
- `evaluation/tests/training/test_encoder.py`, `test_train_on_val_runs_no_val_eval`: the test now spies on
  `train_batches` and asserts that `items[4:]` equals `load_val_transitions`'s rows and that `first` is
  `[0]*4 ++ val_first`. It also asserts `train_metrics.json`'s `best_val_metric == {}`. **Mechanism:** three
  mutations passed the old tests: dropping the concat in `train()`, concatenating as `[val_items, items]`
  (which leaves `first` misaligned), and `if True` for the `{}` guard. Each one now fails a test. This makes an
  existing test stronger; it adds no new test.
- `docs/system/datasets.md:726`: the KuaiRand label now reads "The command for the run that picks the epoch
  count, not yet run:". Right after the new refit sentence, the old label read as if the command were the refit,
  but the command has no `train_on_val`.

## Open findings (non-blocking)
1. `docs/system/datasets.md:723-725`, **unsupported rationale.** The docs say "refit ... because next-day clicks
   drift and the val day is otherwise never trained on", and link `validation.md#seqrec-encoder`. That section
   has no KuaiRand measurement (every KuaiRand row is "pending") and says nothing about drift. The standing plan
   "the final KuaiRand models are refit" is not in `decisions.md` or `roadmap.md`. **Mechanism:** a decision and
   its reason live only in a system page, linked to a page that does not back them. The fix belongs to the
   orchestrator: record the decision in `decisions.md`, or drop the drift clause.
2. Resume doesn't compare the resumed `_resume.pt`'s config with the current `train_on_val`. This predates W10
   (no config is compared on resume). It is harmless as long as refits use a fresh `checkpoint_dir`, as the W10
   flags do.
