## Why
Read `2026-09-26-234034101-e-k64-diagnosis.md`. KuaiRand's final model never sees the val day (the split is train
≤ 05-05, val 05-06, test 05-07), and next-day clicks drift. The standard fix is to refit on train + val for the
final model, with the epoch count chosen beforehand.

## Step
1. Read how `val.parquet` is built (`item_ids` history plus `targets` for the val day; check their time order in
   the ETL) and how the trainer builds training rows.
2. Add `TrainConfig.train_on_val: bool = False`. When true:
   - **Training rows:** also train on the val-day transitions, built from each val row as `item_ids ++ targets`,
     taking the last `max_seq_length + 1` tokens, like a train row.
     - Avoid double-training the history transitions if that is cheap and thin: for example, mask the loss to
       the target positions only. If it is not cheap, state the duplicate fraction (by arithmetic, per dataset)
       and accept it.
     - State which you chose, and why.
   - **logQ frequencies** include those rows.
   - **No val eval and no early stop:** run exactly `num_epochs`. The final epoch's model is the one saved and
     test-scored (`best_model.pt` and the eval files keep their names).
   - Reject `train_on_val=true` together with a val-based early-stop requirement if one would otherwise silently
     apply, following the pattern of the other config rejections.
3. **Tests:** pin the row construction (tail, targets appended in order, masking if chosen) on a tiny hand-built
   parquet, and pin that no val eval runs. Each must fail on its mutation. No new scaffolding beyond a tmp
   parquet.
4. **Docs:**
   - datasets.md § Training: the option, when to use it (the final fit after choosing epochs on val), and that
     test is then scored on the last epoch.
   - § kuairand: one sentence that the final KuaiRand models use it, with a link to validation.
