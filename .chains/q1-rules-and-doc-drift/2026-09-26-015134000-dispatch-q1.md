## 2. Rules to add — `docs/contracts/coding-guidelines.md`
- **D5 extension: no dated or history comments.** No "measured 2026-…", "previously X", "was broken, now fixed", no run logs in code. A measurement lives in `docs/validation.md` + `docs/artifacts/<plan>/`; the comment cites the page section or says nothing. (Existing offenders are fixed in the step that owns their tree: `evaluation/eval_datasets/etl/{yfcc,pubmed}.py` → Q2; `retrieve/src/retrieve/ops/triton/clause_mask.py`, `ops/official/__init__.py` → Q4. Q1 only writes the rule.)
- **D6 extension: what a gate test asserts.** A short table, each row a failure mode and its fix:
  - the mutation check — flip a sign or drop a clause in the function under test, and a real gate goes red;
  - no smoke-only "did not raise", no `is not None`/`isinstance`-only assertions, no test that re-computes the implementation;
  - rejections checked with `pytest.raises(Err, match=...)` so the *reason* is pinned;
  - degenerate inputs (empty, one survivor, all masked) assert exact sentinel values;
  - every non-zero tolerance is stated at its call site with a one-line reason; helpers take no default tolerance;
  - a test that scans the tree asserts it found a non-trivial number of files, and every allow-list entry must still be needed.
- **One home per fact** (also one sentence under AGENTS.md rule 4): each fact lives on one page, others link to it; when a fact is renamed (branch, path, flag, count) grep `AGENTS.md`, `docs/`, `retrieve/docs/`, `README.md` for the old wording and fix every copy.

## 3. Rules to add — `docs/contracts/agent-orchestration.md` §5
- **Fixed-heading dispatch brief**: Step · Read only · Gates (quoted; bit-exact ones marked) · Branch/worktree · Model + concurrency · Out of scope · Verify commands · Return. Plus two standing lines: "the code wins over any doc, note or memory"; "state the mechanism of a bug before fixing it".
- **Proof by kind of change** (short table): refactor → the named gate bit-exact before and after; behaviour change → a test that pins it; performance → before/after with `sm_mhz`, `unstable`, shape, and the *prediction written before measuring*; a slower result is a result and is kept; a ratio between two backends is sampled interleaved (A,B,A,B…) in one process so clock drift hits both arms.
