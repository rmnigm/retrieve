# campaign-final: the final pass's config and recipe

> **Superseded by the FULL-RERUN, not for the paper** ([full-rerun](../full-rerun/README.md)). Kept because current code or docs point here; the records stay on the Hub ([hub-index § Superseded](../hub-index.md#superseded-not-for-the-paper)).

The final pass (roadmap F-REPRO; user directive 2026-10-10) reruns every suite and dataset the campaign drew claims from,
at one frozen library code_version (`campaign-v2.12`, library `e16512f5`; the extension legs from tag `campaign-final`, same library), into `campaign-final/` on the Hub. Every number stays NOT CITABLE until
D1-G passes.

| file | what |
|---|---|

| [`ceiling.sh`](ceiling.sh) | the C6 recall-ceiling checks as script legs, one per bench (`campaign-v2.11/ceiling-int8-laion30m/ceiling_check.py`, quality only) at the points of [`ceiling-points.json`](ceiling-points.json) (the measured ones: goodreads / arXiv and their synth at the v2.10 tune's best clause point, PubMed 16384 / 4096, YFCC synth 4096 / 256, LAION 16384 / 4096); on C6's GPU after the bench's tune legs; LAION's synth p001 reads a scratch `ceil` suite, as the v2.11 driver did |

## The final grid

[`evaluation/config/suites.yaml`](../../../evaluation/config/suites.yaml) holds 4,016 cells in 28 suites: 3,682 in the final grid proper, plus the fixed-d N-sweep extension's 262 (`nsweep-synth`, `nsweep`, `nsweep-codesign` on the seeded LAION subsets laion1m / 3m / 10m, laion30m itself and arXiv 3 M at d256, one box) and the seeds extension's 72 (`seeds-c1`, `seeds-c1-laion30m`, `seeds-c7`, seeds 0-2 on one box); the extension legs run from the `campaign-final` tag (same library); [datasets § Subsets](../../../docs/system/datasets.md#subsets)). The table is
[evaluation § Config](../../../docs/system/evaluation.md#config-one-yaml-per-dataset--suitesyaml), and the counts are pinned
in `evaluation/tests/bench/test_config.py` (`GRID`).

Seeds: seed 0 everywhere, with seeds 0-2 in `filter` only (T2's CIs).

**Folded in:** `c3`, `c3-real`, `codesign-pubmed`, `laion30m-x`, `c7-scorepath` (plus n_probe 32), `tune-q`, `tune-timed`. `v1v2` is covered by `synth`.

**Dropped:**
- `deep`'s V3 arm and its untuned n_lists grids (its official bloom curve stays, paired with triton: F3, C7);
- `filter`'s SilverTorch torch arms (C3 runs on V1 / V2 in `c3` / `c3-real`);
- goodreads-synth's bloom V1 / V2 and its SilverTorch / official bloom arms;
- goodreads-synth SilverTorch n_probe 128 / 512;
- `codesign` goodreads `c2_format` / `c3_year`.

**Retuned:**
- `deep` runs at the tuned n_lists, up to the n_lists / 4 cap. PubMed takes the 21 points of its v2.11 timed fronts.
- PubMed `filter` runs 4096 × {24, 512, 1024}, plus `all5` at 16384 / 2048 and `c3_journal_reverse` at 65536 / 1024.
- arxiv-synth gets nine rates for C1.
- arxiv- and corr-synth SilverTorch is capped at n_probe 512.

## Sizing

73.5 GPU-h: cells plus index builds (`elapsed_s` excludes `build_s`, ≈ 400 s per 30 M job), times the measured 1.15 process overhead (wall over cells + builds). Quality-only tune legs, and the timed tune legs v2.11 measured (goodreads, YFCC, PubMed), are priced from their measured runs; arXiv's timed tune is not measured yet.

| GPU | GPU-h |
|---|---|
| pod d GPU 0 | 16.1 |
| pod d GPU 1 | 21.5 |
| pod 1 | 17.4 (incl. the N-sweep's 6.6) |
| pod b | 18.6 (incl. the seeds legs' 4.1) |

So about 20 h wall, if M1 lets pod d time on both GPUs at once; otherwise pod d runs its two GPU queues in turn, about 37 h.

## After all legs

1. `bench fetch` every `campaign-final/*` subtree, then `aggregate.py LEGS OUT recipe.yaml e16512f5 <prefer>`:
   - within a subtree, the last line per key wins;
   - copies across subtrees must be byte-identical, except where a `<prefer>` subtree wins;
   - every record must be at the library;
   - the recipe's paths and record counts are checked.

   `coverage.py CONFIG_DIR TREE OUT.json` sets the merged tree against every cell `load_matrix` expands from suites.yaml.
   The table is `campaign-final/merged-4016` (`results.parquet` with `dedup.json`, `dedup.csv`, `coverage.json`): 4,016
   records, 0 missing. The first aggregate at the `campaign-final` root (4,001 records) lacked the 15 c3 d256 cells. The three
   `*-d1-st` subtrees are the prefer set. They restore d-run's legs d1-02 / d1-04 / d1-09, whose recipe paths a later
   leg's upload replaced.
2. `bench report --manifest` over the merged tree, with `evaluation/campaign.yaml` set to the one code_version.
3. D1-G:
   - the CPU checks (`research/artifacts/campaign-v2/exhibits/checks.py`: eager vs graph ids, bs 16 < 16 × bs 1);
   - the quality reruns: `d1g_quality.py plan`, `d1g_run.sh`, then `d1g_quality.py compare` per GPU tree.
4. T1 from the merged tree only (`research/artifacts/campaign-v2/exhibits/run.sh`).

The state of each step is in [validation](../../validation.md).
