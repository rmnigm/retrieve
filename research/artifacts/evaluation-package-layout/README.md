# evaluation-package-layout artifacts

Raw scripts and outputs behind evaluation-package-layout.md
§11 (roadmap C5), so the numbers can be re-derived.

- `c5_gpu_run.sh` — the runbook: the one-cell gate (`bench run … silvertorch --backend
  triton` on goodreads-d128 `c0_genre`) then L4-b, under `flock /workspace/gpu.lock`.
- `l4b_chunk64.py` — `bench run` with `run.QUALITY_CHUNK = 64`; the harness constant is
  untouched.
- `c5_compare.py gate <jsonl>` — every C5 record against the C4 record with the same key
  block and `code_version`: key block equal, `quality` equal to the digit, no graph
  `reason`; `c5_compare.py l4b <jsonl>` — the chunk-64 `linr_v4` record against the
  re-derived golden and C4's chunk-16 record.
- `c5/` — `provenance.txt`, `driver.log`, the two `bench run` logs, `results/` (6 gate
  records + samples + `flat.csv`) and `results-l4b-chunk64/` (3 quality-only records).
  The `_parity/` spill files (~680 MB) are regenerated by every run and were deleted.
